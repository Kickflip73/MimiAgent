使用 `speech` 工具，先通过 `settings` 查看实时默认值、音色与引擎能力。引擎只有 `macos`、`kokoro`、`breeze`；`auto` 是选择策略，不是第四个引擎。ChatTTS 已移除，不要通过 Shell 或旧脚本启动它。

## 阅读稿

`prepare` 的 `input` 是原始文本，返回独立阅读稿和警告，不会改动对话原文。整理包括 Markdown、表格逐行口述、日期、百分数、单位和常用缩写。代码和裸链接会被提示替代，遇到科学公式、版本、编号、英文专名时不要猜测含义或发音。

如用户要求自然讲解，可在保留事实、数字、限定条件和顺序的前提下改写阅读稿：表格转为有名称的句子；保留重要比较；英文专名首次读完整称呼；代码描述用途而非逐个读符号。不要把全文朗读擅自改为摘要。需要逐字朗读或已经人工整理过的稿件，使用 `textMode: "verbatim"`。

`speak` 用于用户要求“读出来”：Breeze 第一段音频到达时就通知对话播放器，在浏览器允许时开始播放；不要先等工具返回再安排朗读，也不要重复合成。`synthesize` 同样提供提前可播放入口，但不自动播放。两者完成后都保留完整 WAV，`play` 复用已生成的 audioId。浏览器可能要求用户点击启用声音；不要声称已经从用户扬声器播放。回答旁的喇叭按钮使用默认设置，Breeze 支持边合成边播放，其他两个引擎合成后播放。生成状态不确定时只 inspect 原操作，不自动重新合成。

长故事必须保留全文。Breeze 会按段连续生成，超时按“持续无进展”计算，不按整篇总时长；繁忙请求会等待，不需要另换音色或引擎重试。超过单次字符上限时按原文自然章节拆分顺序朗读，不得摘要、精简剧情或删尾。失败后不要擅自缩短再生成；先查看原操作状态，明确告知未完成部分。多角色广播剧也不得因耗时自动改为短故事。

`409 busy` 只说明有请求占用引擎，不说明服务卡死，更不能据此认定那个请求属于当前会话。即使当前会话超时，也可能是别的会话正在合成。不要通过 Shell、kill、pkill、launchctl kickstart 或重启模型服务来抢占；进度日志持续产生 piece_done 就是仍在工作。需要重启时必须先向用户说明会中断其他合成并取得明确指令，不能以“修复 busy”为由自行重启。

单音色长文朗读必须整篇使用同一个参考音色。当前本地服务以 stable_voice 锁定分段 seed 和参考；描述型仅首段设计，后续复用首段参考，参考不可用时会失败而不是换声。不得为各个小段分别生成音色、改描述或换 seed。需要多角色时才显式按角色绑定各自固定参考，不能混入普通单人朗读。

## 引擎与音色

- `configure` 保存全局默认值；普通 `synthesize` 的 engine、voice、speed、language、instructions、textMode 只影响本次。
- macOS 和 Kokoro 只支持现有音色与速度，不支持描述生成。Breeze 的 `instructions` 可以描述语言、音高、音质和说话方式。不要把描述当作引擎无关能力。
- `voice_save` 用 `id`、`name` 加上述选项保存预设或描述配置。描述每次重新合成，不能保证声纹完全一致。
- `voice_generate` 使用同样参数，`input` 为最多 80 字的自然示例稿；生成 Breeze 参考声音并持久化，再用 `voice: "saved:<id>"` 复用。它生成的是合成参考音色，不是对真人音频克隆。结果未确认时保留原记录、报告状态，不重试或换 ID 绕过。
- `engine_voice` 用 `engine`、`voice` 记住每个引擎的默认音色，不切换当前默认引擎。`configure` 选择默认引擎；阅读方式和语速对保存音色同样生效。
- `voice_clone` 的 `input` 是已有 PCM16 单声道 WAV 的绝对路径（1～30 秒），`transcript` 是录音原话，另传 `id` 和 `name`。保存 Breeze 参考音色后可用 `saved:<id>` 试听和切换。Web 可录音或上传常见音频，先转换为 WAV。未确认结果不自动重试。
- `voice_remove` 删除配置；不删除已经生成的会话音频或服务端参考文件。
- `settings` 中 ready 的保存音色可以直接用于单次朗读或 configure。切换引擎时同时选择该引擎音色；不要复用旧引擎的音色 ID。

判断保存类型必须查看实时 `settings.profiles`：有 `referenceId` 的 ready 音色已经保存参考声音，不能因为 options 中仍有 instructions 就说它是“仅描述型”；描述在这种情况下只是创建时的元数据。没有 referenceId 且只有 instructions 的才是描述配置。不要根据旧对话、名称或记忆猜当前默认音色。

固定参考不保证不同稿件或长文本前后声纹完全一致，也不保证“真人克隆每次完全一模一样”。较长内容会分段生成，模型仍可能发生风格漂移。用户报告突变时先核对当前音色和参考，再如实报告模型限制，不能把固定参考误判为每次重新设计。保存失败只报告返回的真实错误；本地产生 referenceId 不代表服务端已保存。不要把一次 HTTP 400 概括为该能力不可用，也不要重试或换 ID 绕过未确认记录。

语速范围 0.5～2。Breeze 通过本地 FFmpeg atempo 保持音高变速，macOS 用系统语速，Kokoro 用原生 speed。服务不可用时报告具体引擎错误，不静默切换音色或引擎。


## 预览与确认
用户只要求定制/尝试声音时，用 `voice_preview`（id、name、input 示例稿、engine=breeze、instructions），不直接用会保存的 voice_generate/voice_clone。预览不加入音色列表、不切换默认值。用户试听并明确确认后，再 `voice_confirm`（id）；不满意则 `voice_discard`（id）。`voice_remove` 删除已保存音色；默认音色被删除后回到引擎默认。Web 的文字描述、录音、上传三种方式均先预览，用户点击保存才注册音色。旧的显式保存接口仅用于用户已经确认要保存的操作。
