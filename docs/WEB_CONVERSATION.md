# Web 对话呈现

## 本次实现

消息分三层：角色与元信息外壳、内容块、执行过程。用户和 Mimi 使用同一个气泡组件，四角均为 20px；通过左右对齐和两种中性色区分角色。对话最大宽度 960px，消息底部留白 22px，元信息放在这段留白中，悬停不会让内容跳动。

执行过程按原始事件顺序分段。`afterAnswer` 仍表示事件发生在第几段回答之后，展示时归入下一段回答的上方。没有下一段回答时独立展示，停止或失败也不创建虚构回答。实时输出、断线恢复、本地缓存和持久历史使用同一规则，不改变原始 Session 数据。

`message-view.js` 将正文变成类型明确的内容块，当前包含文字、图片、语音和视频。气泡负责视觉与动效，文字渲染器负责 Markdown，图片渲染器复用本机附件预览。流式更新只替换文字块，不重新挂载气泡、图片或执行过程面板。

复制与时间默认隐藏，悬停或键盘焦点进入当前消息时展示。触屏保留复制按钮。新气泡以 300ms 的轻微回弹呈现；完全离开视野后再次进入使用 180ms 的轻微位移，不反复弹跳。IntersectionObserver 只跟踪气泡，不逐帧测量整个聊天列表；移除节点时释放观察与动画。减少动态效果或隐藏页面时不播放动画，动效不延迟消息显示或执行完成。

## 后续扩展顺序与边界

| 内容 | 数据与交互约定 | 下一步 |
| --- | --- | --- |
| 文件 / 任务卡片 | 类型、标题、摘要、状态及明确动作；避免把状态塞入正文 | 接入已有任务与交付回执，保留文字降级表示 |
| 网页预览 | 标题、来源、URL、摘要 | 校验链接后显示预览卡，明确打开外部页面 |
| 交互式 UI | 版本化的受限组件描述及显式动作 | 先支持表单、选项、表格；动作走已有主机接口 |
| HTML 成果页 | 独立成果引用，与聊天渲染树隔离 | 使用隔离预览，不执行模型正文里的脚本 |

上表是后续协议约定，当前已启用文字、图片、音视频与 Markdown 代码块。不要因准备扩展而引入通用插件系统或新持久化协议。新增类型时先确定真实生产者和验证边界，再添加一个内容块渲染器；未知类型降级为可阅读的摘要或附件链接。

任何内容块都复用现有消息身份、时间、排队和重试语义。原始历史仍是事实来源，界面状态不回写为模型消息。交互动作不能从 HTML 或模型内容中获得额外权限。

## 验收

- 历史、实时、刷新与中断：每段执行过程位于其对应回答之前，末尾过程不丢失。
- 长文本、代码和图片不超出气泡；短文本保持自然宽度。
- 悬停与键盘焦点只显示当前消息的元信息，布局高度不变。
- 上下滚动重入轻柔呈现；流式文字增量不重复触发整颗气泡动画。
- 触屏、窄屏及减少动态效果模式可正常读取、复制与展开过程。

## 音视频实现与边界

Web 上传以内容摘要命名原文件，单独准备小型元数据；IPC 仅携带附件 ID。音频经 ffmpeg 有界解码，再由单个短生命周期 whisper.cpp 进程识别，WebM 缺失时长时从解码后的 WAV 获取。视频最多采样 8 帧，通过已有原生图片输入交给模型。Session 保存播放引用、转写和用户原始展示文字，不写入二进制；压缩后的模型历史保留转写文字。

消息气泡复用媒体块渲染器，语音使用紧凑的播放/暂停、进度条、时长及下方转写，视频使用浏览器控制条；所有媒体不自动播放。代码块保留横向滚动，语言标题与悬停复制入口。录音仅由用户点击触发，取消、停止、会话切换、页面退出和异常均释放设备。上传/识别失败保留草稿，删除后的异步响应不能重新插入附件。

模型输出使用 Markdown 媒体链接或反引号绝对路径引用，无需新增可执行消息协议。代码示例内的媒体路径不生成预览。本地输出服务要求当前 assistant 历史引用、工作区/生成媒体目录约束、真实文件路径和格式检查；支持 Range 回放，不暴露任意本地文件。暂不支持视频音轨理解、原生音频语气理解、任意 HTML 或自动执行的卡片。

## 图片上下文计量

上下文估算识别 SDK 的 `input_image` 和工具结果 `image` 内容块，Base64、URL、文件引用不按正文字符数计量。当前跨提供商预估为每张 4096 tokens，`original` 细节为 32768；这是规划预算，不是供应商计费值或严格上界。真实用量以供应商回执为准，不同模型的 tile/patch 算法仍可能有偏差。图片数量会累计占用，真正过大的文字/工具协议单元仍受原预算限制。

只用于文字分析的摘要和引用提取省略原生图片编码，保留图片存在标记、已有文字观察及 URL/文件引用；普通文本中的 Base64 仍按文本计量。主视觉模型的输入、Session 原始事实和快照完整性摘要不受这层投影影响。这样避免一张数 MB 图片触发无意义的语义压缩或假性上下文溢出。

### 图片追问与执行头像

图片的原始字节保存在本地附件存储，Session 只保存内容哈希引用。模型传输视图会恢复最近八条用户消息内最后一组图片（最多八张、合计 20 MB），并按图片能力选择自动模型路由。新上传图片优先，不重复附带旧图；禁止读取 Session 的执行不会恢复历史附件。缺失、损坏、符号链接或非法引用不会作为图片传入，也不会编造画面。新上传图片遇到明确指定的不兼容模型仍报告能力冲突；显式切回文字模型时，旧图片保持文字历史，不强迫切换模型或阻断普通文字请求。旧 Session 可读取既有 daemon 附件存储。

原生图片输入不依赖名为 vision 的工具；本轮 Host 图片输入与能力声明优先于 Memory 中的历史故障结论。执行过程从第一步起拥有猫咪头像，回答到达后复用同一消息容器。已完成回答的耗时、时间和复制按钮在鼠标悬停或键盘聚焦时显示；触屏保留可访问的操作。
